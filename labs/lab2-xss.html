Débutant 15 min XSS réfléchi

Le formulaire bavard

Le livre d'or de NeoCorp affiche chaque message sans le filtrer. Votre objectif : faire exécuter du JavaScript par la page, comme le ferait un attaquant.

Démonstration locale
Briefing

Un livre d'or, un rendu trop confiant.

Le site affiche votre message grâce à innerHTML. Tout ce que vous saisissez est donc interprété comme du HTML, y compris des gestionnaires d'événements.

  • Objectif : déclencher du JavaScript dans la page et récupérer le flag.
  • Indice technique : le champ n'est pas échappé avant insertion dans le DOM.
  • Périmètre : ce laboratoire uniquement. Aucun serveur, aucune victime réelle.

Important : ce lab est volontairement vulnérable. Le code injecté s'exécute dans un cadre isolé (iframe sandbox) sur votre appareil, jamais dans la page principale. Ne reproduisez jamais ce test sur un site tiers.

Valider le flag

Lorsque le XSS s'exécute, une fenêtre de ce laboratoire affiche le flag. Recopiez-le ici.

Flag capturé

Vous avez déclenché un XSS réfléchi : la charge est renvoyée par la page et exécutée dans le contexte du site. Un attaquant pourrait voler une session, modifier l'apparence du site ou piéger les visiteurs.

Correctifs : échapper les sorties selon le contexte, éviter innerHTML pour les données utilisateur, utiliser une politique CSP stricte, marquer les cookies sensibles HttpOnly et employer un assainisseur éprouvé si du HTML est réellement nécessaire.

Indices

Indice 1 — Ce qui est interprété

Le message est inséré via innerHTML. Les balises HTML sont donc interprétées par le navigateur au lieu d'être affichées comme du texte.

Indice 2 — Les scripts ne s'exécutent pas toujours

Une balise <script> injectée par innerHTML ne s'exécute pas. Utilisez plutôt un attribut événementiel sur un élément qui déclenche une erreur de chargement.

Indice 3 — Une payload classique

Essayez :

<img src=x onerror=alert(1)>

Le réflexe

Face à une entrée reflétée, demandez-vous toujours : « où ce texte est-il réinséré, et dans quel contexte ? » HTML, attribut, URL et JavaScript n'ont pas les mêmes règles d'encodage.
