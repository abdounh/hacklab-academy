Dans l'ombre du code source

Un site vitrine peut révéler bien plus que ce qu'il affiche. Votre mission : retrouver un secret oublié par un développeur dans le HTML de NeoCorp.

Aucun outil à installer
Briefing

NeoCorp a mis son site en ligne un peu trop vite.

L'équipe a déployé la nouvelle page d'accueil sans revue de code finale. Un commentaire de développement est resté dans le HTML, avec un accès de démonstration.

  • Contexte : vous inspectez le site vitrine de NeoCorp dans un cadre autorisé.
  • Objectif : trouver le flag caché dans la page cible.
  • Méthode : ouvrir la page, afficher son code source ou utiliser les DevTools.
  • Périmètre : uniquement la page locale affichée ci-dessous.

La cible

Locale
https://neocorp.example/
Le site s'affiche dans un cadre isolé. Ouvrez-le seul pour inspecter son code. Ouvrir la cible dans un nouvel onglet

Valider le flag

Le flag est au format HACKLAB{...}. Recopiez-le exactement, sans espace.

Flag capturé

Les commentaires HTML oubliés, les variables JavaScript, les source maps et les fichiers de sauvegarde exposent parfois des secrets. Ici, un accès de démonstration a fuité dans une page publique.

Impact : réutilisation d'identifiants, accès à un environnement interne, cartographie de l'infrastructure. Correctif : revue de code, outil de détection de secrets, rotation des identifiants et suppression des commentaires sensibles avant déploiement. Un secret ne doit jamais être placé côté client.

Indices

Indice 1 — Par où commencer ?

Ouvrez la page cible dans un nouvel onglet, puis affichez son code source avec Ctrl+U (ou clic droit → Afficher le code source).

Indice 2 — Quoi chercher ?

Les développeurs laissent parfois des commentaires <!-- ... -->. Cherchez le terme DEV-NOTE dans le document.

Indice 3 — Où précisément ?

Le commentaire se trouve vers le pied de page du site NeoCorp, juste avant la fermeture de la balise </body>.

Le réflexe

Le code source est la première chose qu'un auditeur consulte. Une page peut sembler propre tout en contenant des commentaires, des endpoints ou des identifiants.

Utilisez les DevTools : onglet Éléments pour le DOM, Sources pour les fichiers chargés.
